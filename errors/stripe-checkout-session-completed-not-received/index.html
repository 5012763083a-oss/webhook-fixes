Stripe checkout.session.completed not firing or not received: checklist

First work out whether Stripe didn't send the event or your endpoint didn't accept it. Open your webhook endpoint in Workbench (Webhooks) and check the Event deliveries tab. Each event is listed as Delivered, Pending or Failed, with the HTTP status of every attempt.

No delivery attempt listed: Stripe isn't sending it to this endpoint

  1. Event type not selected. The endpoint only receives the event types you chose when you created it. Add checkout.session.completed.
  2. Wrong mode or account. Sandbox (test) and live have separate endpoints. A test-mode checkout never reaches a live-only endpoint, and the reverse is also true.
  3. Connect scope. If the Checkout Session is created on a connected account (direct charges), the event happens on that account. Only an endpoint with Events from: Connected accounts (API: connect=true) receives it. A "Your account" endpoint won't.
  4. You're testing with the CLI. stripe listen --forward-to forwards events to your local URL using the CLI's own whsec_. That doesn't send anything to your Dashboard endpoint. Use --forward-connect-to for Connect events.
  5. The session never completed. The event fires only when the customer finishes Checkout. Abandoned sessions produce checkout.session.expired instead.

Attempts listed but Failed: your endpoint rejected it

  • 3xx: Stripe doesn't follow redirects. See 307/308 redirects.
  • 400 from your code: usually a signature failure. See No signatures found and Next.js raw body.
  • 401/403/404/405: auth middleware, the wrong path, or the route doesn't accept POST.
  • Timeouts: fulfilment work done before responding. See webhook timed out.

It fired, but the order wasn't paid

With delayed payment methods (bank debits and similar), the session can complete while payment_status is still unpaid. Stripe's fulfilment guide says to check payment_status before fulfilling, and to handle checkout.session.async_payment_succeeded, which fires when a delayed payment later succeeds. It also suggests handling checkout.session.async_payment_failed, for example to email the customer.

switch (event.type) {
  case 'checkout.session.completed':
  case 'checkout.session.async_payment_succeeded':
    if (event.data.object.payment_status !== 'unpaid') await fulfil(event.data.object.id);  // idempotent
    break;
  case 'checkout.session.async_payment_failed':
    await notifyFailed(event.data.object.id);
    break;
}
