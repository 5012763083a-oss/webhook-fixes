Method PUT is not allowed by Access-Control-Allow-Methods in preflight response

The preflight answered, but its Access-Control-Allow-Methods doesn't list the method you're using (often PUT, PATCH or DELETE). GET, HEAD and POST are always allowed.

Fix

Access-Control-Allow-Methods: GET, POST, PUT, PATCH, DELETE

This header must be on the OPTIONS response. * works only for requests without credentials. Also check that your router has an OPTIONS handler for that path: some frameworks return 405 for unhandled OPTIONS, which fails with a different error.
